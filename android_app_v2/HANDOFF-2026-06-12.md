## 1. 第一波：录音笔引擎 + 宿主层同步

**背景**：v2 复用 Java 录音引擎，但**宿主层是新写的**。每次 `../android_app`（WebView 版）的笔逻辑升级，必须手动把宿主层同步到 v2。映射关系见长期记忆 `v2-pen-logic-sync`。

做了：
- **引擎逐字节同步**：`android_app_v2/.../PenController.java` ← 覆盖复制 `../android_app/.../PenController.java`，`diff -q` 校验 **IDENTICAL**。带入用户最近的引擎内改动：补传放弃统一 2 小时、退避重试封顶、放弃封顶用持久化墙钟、penlog.txt、黑屏/后台靠通知振动、开机自动录制检测、`isRecording()`。`PhoneMicService`/`PenKeepAliveService` 此前已同步（只差 MeiliActivity intent）。
- **新增 Listener 回调 `onPenPowerOnRecordDisabled()`**：笔「开机自动录制」被关 → 结束这段误录 + 提示关机重开。实现在两处：生效路径 `RecordingControllerImpl` + 备份壳 `ConsultantActivity`（后者虽不是 v2 入口，但也 implements Listener，不实现编译就挂）。
- **「假录音中」兜底**（对齐用户改的 `bridgeGetState`/`onResume`）：UI 显示录音中但笔其实没在录 → 拉回 Idle。v2 在 `RecordingControllerImpl.attach()` 快照纠正 + 每 3s `consistencyWatch` 巡检。备份壳 `ConsultantActivity` 的 `bridgeGetState`/`onResume` 也补了（含 `getRecordingElapsedSec` 计时前对齐）。

**验证过的等价点（架构不同但行为一致，不是漏）**：
- 连上后开录：WebView 按 `onPenRecordStatus(recording)` 分支调 `markCurrentSessionAppInitiated`；**新引擎已把这段去重逻辑收进 `startRecording()` 内部**（笔已在录→标记 app-initiated + 回推 recording，不重复开始），所以 v2 桥一律调 `startRecording` 即可。
- 计时不归零：v2 用持久化墙钟 + 引擎 `onPenRecordDuration`「只向前对齐」，VM 跨 tab 存活，比 WebView 的 JS 计时更稳。

## 2. 第二波：网页版逐项对齐审计（10 个差异，全修）

4 个子 agent 分别审 web `consultant.html` JS UX 的一个切片 vs v2。**「从陪伴笔同步」sheet 本体其实已端到端实现**（在 **待整理 tab**：`PendingScreen`/`PendingViewModel`，不在首页），所以那块没缺功能。查出并修复的 10 个差异：

| # | 差异 | 级别 | 修法 |
|---|------|------|------|
| 1 | 「从陪伴笔同步」从首页点了**只切 tab、不开 sheet** | HIGH | `AppScaffold` 一次性信号 `openSyncSignal` → `PendingScreen` 进页自动开 sheet |
| 2 | **「陪伴笔已连接」提示完全没有** | HIGH | 新事件流 `penEvents`，`onPenConnected` false→true 弹一次 |
| 3 | 大圆钮**「唤醒中」「保存中」长得跟空闲一样** | HIGH | `CompanionButton` 加 `starting`(转圈+玫瑰渐变+可取消)/`enabled`(保存中置灰不可点) |
| 4 | 选了笔没连时**无「请先连接陪伴笔」提示** | HIGH | `statusText(source)` 据 source+penConnected 给提示 |
| 5 | **错误/归属拒绝/开机自录被关的 toast 被悄悄吞**（塞在去重的 `Idle.errorMessage`，相同文案不重弹、还被随后的 Idle 覆盖） | MED | 改走一次性事件流 `penEvents`（4 个 agent 共同指出的根因） |
| 6 | 后台补传落地后**首页「N段待整理」不刷新**（`onPenUploaded` 是空实现） | MED | 新事件流 `penListChanged` → `HomeViewModel.loadPending()` |
| 7 | 待传/失败/连接指示**只靠 push、回调漏报就停在旧值** | MED | 3s `consistencyWatch` 兼做兜底回拉 `isPenAlive/pendingCount/pendingFailedCount`（对齐 web 轮询自愈） |
| 8 | 导入机身片段后**只刷一次、占位卡还没落地** | MED | 改 3s/10s 分档刷新（对齐 web） |
| 9 | **Cookie 轮换后笔在非首页自发录音可能用旧 Cookie 上传失败** | MED | `onNeedContextRefresh` 钩子：connect/record-status 回调里重注 Cookie（`RecordingModule.init` 接 `::refreshUploadContext`） |
| 10 | 同步 sheet「没连接笔」被**误显示成「没有文件」** | LOW | `openPenSync` 开 sheet 前先校验 `isPenConnected` |

**核心新机制（写需求/后续维护要知道）**：
- 笔的一次性提示一律走 **`RecordingController.penEvents: SharedFlow<String>`**，UI collect→Toast。**别再塞 `Idle.errorMessage`**——会被 StateFlow 去重或被随后的 Idle 覆盖吞掉。
- 后台片段落地走 **`penListChanged: SharedFlow<Unit>`**。
- **「假录音中」巡检必须加 `currentSource == Pen` 守卫**，否则会误杀正在进行的手机麦录音（手机麦时 `penController.isRecording()` 恒 false）。

**有意没做的 LOW 项（与网页本就一致 / 属同款引擎限制，不是漏）**：
- 「信号断开自动重连」那行字——网页自己也不显示（红线不露「录音」字样）。
- 机身列表迟迟不返回时一直转圈——网页也无超时。
- 退出扫描页未连接时靠 8s 兜底回 Idle（非瞬时，但不卡死）。
- 录音中点来源 cell 无「锁定」涟漪反馈——网页也是静默忽略。

## 4. 部署 / 分发现状（重要，别踩）

- **APK 没有上传到任何地方**，只在本地：`app/build/outputs/apk/debug/app-debug.apk`。
- **`/download` 页面 + `tools/deploy_app.sh` 是给生产 WebView 老 App 的**：deploy 脚本硬编码构建 `../android_app` 的 **release** 包、校验固定 keystore 证书、scp 到服务器 `app-release.apk`（即 `/download` 发给真实顾问的「刁姐陪伴.apk」，包名 `com.aibeautyfulwomen.gongpai`，带强制更新）。
- **v2 是另一个包**：debug 包 = `com.aibeautyfulwomen.gongpai**.v2**`（build.gradle 特意加的后缀）、debug 签名，**和线上包共存、不撞签名**。
- **绝不能把 v2 覆盖到 `/download` 的 `app-release.apk`**：会把没真机验证的 dev 包发给全体顾问，且包名不同 + debug 签名根本不会更新他们的 App。
- 若要让 vivo **从网页下载装 v2**：需在服务器**另起一个路径**（如 `/download/v2`，不碰生产文件），属后端改动（加路由 + push + 重启 gongpai），用户尚未拍板。当前因 `adb` 连不上，真机安装一直被卡。
